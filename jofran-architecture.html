01

Design principles

Five constraints shape every decision below. They come from the country this platform serves, not from a generic EdTech checklist.

  • Low-bandwidth-first. Mobile data in Timor-Leste is costly outside Dili. Pages render server-side, lesson video is transcoded to adaptive bitrate, and API payloads are paginated aggressively — the app should feel usable on a 3G link, not just tolerate one.
  • Multilingual by construction, not by patch. Every content model carries locale variants from the schema up. There is no "default English, translate later" — Tetum, Portuguese-influenced Bahasa Indonesia, and English are peers in the data model.
  • Role-scoped by construction. Every query is filtered by schoolId (and, below that, classId or studentId) at the guard/policy layer, never left to the controller to remember. A scoping bug here is a privacy incident, not a UX bug.
  • Child-safe AI, always reviewable. No AI output reaches a student unlogged. Every AI interaction a child has is visible to that child's teacher and guardian — this is a transparency feature, not a surveillance one.
  • Boring, operable infrastructure. Managed services (RDS, ElastiCache, Fargate) over self-run clusters, so a two- or three-person engineering team can run this in production without a dedicated SRE function.

03

System architecture

A request takes one of three paths: the REST path through the API, the WebSocket path for anything live, or a direct-to-storage path for media that never needs to touch the API at all.

The API itself is a modular monolith, not a microservice mesh: one NestJS deployable, one database, module boundaries that mirror the domain (§05). At Jofran's scale — six roles, one country, a handful of schools at launch — the operational cost of a service mesh would outweigh its benefit; the module boundaries are drawn so that extraction later (e.g. peeling off the AI module) stays possible without a rewrite.

The same NestJS process serves two API styles, deliberately: REST for auth, webhooks, and anything a mobile client or a simple CRUD screen needs, and GraphQL for the composite dashboard screens — a Principal's school-wide view, a Parent's multi-child summary — where the client's exact shape varies by role and a REST endpoint would either over-fetch or multiply into a dozen role-specific routes.

04

Roles & access control

Six roles, and exactly one of them is allowed to see more than a single school.

Platform-wide

Super Administrator

Create/suspend schools, manage curriculum templates, view cross-school analytics, impersonate for support (fully audited).

One school

School Administrator

Manage staff accounts, classes and enrollment, and the school's subscription.

One school

Principal

Read access across all classes and teachers in their school; approves curriculum deviations; messages parents school-wide.

Assigned classes

Teacher

Creates and grades lessons/assessments for their own classes; messages the parents of their own students.

Own child(ren)

Parent

Views a linked child's progress, attendance and homework; messages the teacher; receives notifications.

Own account

Student (Grade 1–6)

Takes lessons and quizzes, views own progress and badges, chats with the guardrailed AI tutor.

In code, this is a NestJS @Roles() decorator plus a policy guard that resolves scope from the JWT claims (schoolId, and for teachers a cached list of classIds) and injects it into every Prisma query — a controller can never accidentally "forget" to filter, because the unscoped query doesn't compile against the repository layer's types.

Data model

A representative slice of the Prisma schema — the fields that carry the tenancy and locale decisions from §01 through the actual tables.

// prisma/schema.prisma — representative models, not the full file

model School {
  id            String   @id @default(cuid())
  name          String
  municipality  String   // e.g. Dili, Baucau, Ermera
  plan          SchoolPlan @default(PILOT)
  users         User[]
  classes       Class[]
}

model User {
  id            String   @id @default(cuid())
  role          Role     // SUPER_ADMIN | SCHOOL_ADMIN | PRINCIPAL | TEACHER | PARENT | STUDENT
  schoolId      String?  // null only for SUPER_ADMIN
  locale        Locale   @default(TET)
  identities    UserIdentity[]   // linked Google / Microsoft accounts
  guardianOf    Guardianship[]   // PARENT → STUDENT links
}

model Lesson {
  id            String   @id @default(cuid())
  unitId        String
  grade         Int      // 1–6
  variants      LessonLocale[]   // one row per locale, never a fallback string
}

model Attempt {
  id            String   @id @default(cuid())
  studentId     String
  assessmentId  String
  score         Float?
  aiFeedback    String?  // set by ai-grading worker, in the student's locale
  gradedBy      GradedBy // AUTO | AI | TEACHER
}

model ProgressRecord {
  studentId     String
  skillId       String
  mastery       Float    // 0.0–1.0, EWMA over Attempts
  @@unique([studentId, skillId])
}

Every tenant-owned model carries schoolId either directly or one join away, and every content model (Lesson, notification templates, assessment prompts) stores locale variants as rows, not as a JSON blob with an English key — so a missing Tetum translation is a query result, not a runtime string-key miss.

07

Authentication

Short-lived access tokens, rotating refresh tokens, and two OAuth providers feeding the same identity model.

  • Passwords hashed with argon2id; never logged, never returned in any payload.
  • OAuth identities live in a separate UserIdentity table (provider, providerId, userId) so a school-issued Google Workspace account and a password-based fallback can resolve to the same profile.
  • Guards read role and scope from JWT claims; a stale claim (e.g. a teacher reassigned to a different class) is caught within one access-token lifetime — at most 15 minutes.

Real-time layer

A NestJS WebSocket gateway, fanned out across instances with a Redis pub/sub adapter so a message published from one API pod reaches sockets connected to another.

ChannelRoom keyUsed for
Live classclass:{classId}:liveTeacher starts a session; students joining see a presence roster and synced quiz state.
Notificationsuser:{userId}New grade, message, or announcement pushed as a badge update without a page reload.
Leaderboardquiz:{quizId}:boardLive-ranked score updates while a class quiz is in progress.
Messagingthread:{threadId}Typing indicators and delivery receipts on teacher–parent threads.

WebSocket connections authenticate with the same short-lived access token as REST — a socket is dropped, not silently kept alive, when its token expires, forcing the same 15-minute refresh discipline as the HTTP path.

Caching strategy

One Redis instance, four distinct uses, kept separate by key prefix.

session:{userId}                       // active session, TTL = refresh window
refresh:{tokenId}                      // rotation/reuse-detection set
ratelimit:{ip}:{route}                 // sliding window, nestjs-throttler
curriculum:{grade}:{subject}:{locale}  // TTL 1h, warmed on publish
leaderboard:{classId}:{quizId}         // sorted set, live only during an active quiz
presence:{classId}                     // live session roster, WS gateway
bull:*                                 // BullMQ's own queue/job state

Curriculum content is the highest-traffic read and the least volatile write — it is cached aggressively (1 hour TTL, explicitly warmed rather than left to expire cold) and invalidated eagerly by the cache-invalidation queue the moment an editor publishes a change.

11

AI layer

The AI layer is a loop, not a feature: every attempt a student makes feeds the model that decides what they see next.

AI Teacher Jojo

Jojo is the one AI persona a student ever talks to — the same character across reading, writing, listening and speaking, not five separate bots wearing one mascot. Behind that single voice, the AiModule routes each task to whichever OpenAI model fits its cost and latency profile, rather than sending everything to the largest one.

FeatureModelWhy this model
Jojo — chatGPT-5 Miniescalates to GPT-5Turn-based conversation is high-volume and latency-sensitive; only a low-confidence turn escalates to the larger model.
Reading AssistantGPT-5 MiniShort, frequent comprehension feedback — cost scales with every question a student reads.
Writing AssistantGPT-5 MiniGrammar and structure feedback on constructed responses; same cost profile as grading.
Listening AssistantGPT-4o Mini TTSSpeaks Jojo's replies and lesson text aloud, in the student's locale.
Speaking AssistantGPT-4o TranscribeTranscribes a student's spoken answer for pronunciation and fluency practice.
Adaptive LearningGPT-5 Mini + GPT-5 weeklyPer-attempt scoring stays cheap; only the periodic class-wide mastery re-calibration uses the larger model.
Story / Quiz GeneratorGPT-5Generated once per curriculum unit and cached, not per student — the higher-quality model is affordable at that volume.
Assessment EngineGPT-5 Miniescalates to GPT-5Rubric-based grading; only ambiguous or low-confidence answers are re-graded by GPT-5 before a teacher sees them.
Parent Report GeneratorGPT-5 MiniTemplated weekly summaries, batched overnight by the report-generation queue (§09).

Two more uses sit alongside the table above: adaptive difficulty biases the next-question selector toward skills below a mastery threshold (the loop diagrammed above), and translation assist drafts first-pass Tetum/English/Bahasa Indonesia curriculum content — always reviewed and approved by a human curriculum editor before publish, never auto-published.

Child-safety guardrail Every conversation with Jojo is logged and visible to that student's teacher and guardian — this is a transparency feature, not surveillance. Lessons for grade 1–2 (ages 6–8) show no unreviewed AI output; only content a teacher has explicitly marked reviewed reaches the youngest students.
12

Storage & media

S3 in ap-southeast-1, with a deliberately different caching policy for public curriculum media versus a student's own work.

jofran-media-prod/
├── curriculum/{grade}/{subject}/{lessonId}/…    // video, audio, worksheets — public, CDN-cached, long TTL
├── submissions/{schoolId}/{studentId}/{assessmentId}/…  // uploaded homework — private, signed URL only
├── certificates/{studentId}/{badgeId}.pdf       // generated on award, private
└── avatars/{userId}.jpg                         // public, small, CDN-cached

CloudFront sits in front of curriculum/ and avatars/, where long-lived caching helps every school. submissions/ and certificates/ are never CDN-cached and are only reachable through a short-lived (5-minute) signed URL the API issues after checking the requester's scope — a student's homework photo is not a public asset just because it lives in the same bucket.

13

Internationalization

Tetum, English, and Bahasa Indonesia are peers — none of them is the "real" content with the others as translations bolted on.

  • Locale codes: tet · en · id, stored per user and defaulted from the school's municipality at enrollment (editable any time).
  • UI strings: next-intl message catalogs per locale, loaded server-side so a slow device never renders an English flash before the correct locale hydrates.
  • Content: every Lesson, notification template, and assessment prompt has one row per locale in the database — a missing translation surfaces as a content-team task, not a silent English fallback in production.
  • The AI tutor and grading feedback always respond in the student's set locale, not the browser's.
  • Formatting: dates and numbers go through Intl.NumberFormat/Intl.DateTimeFormat per locale (Bahasa Indonesia's comma decimal separator differs from Tetum/English usage); all scheduling and cron runs on Asia/Dili (UTC+9).
14

Infrastructure

One region, one VPC, a clear line between what's reachable from the internet and what isn't.

A note specific to this deployment: Timor-Leste has no in-country AWS region, so ap-southeast-1 (Singapore) is the nearest compliant option — worth stating explicitly for any future data-residency conversation with the Ministry of Education, rather than leaving it implicit in a Terraform variable.

15

Security & compliance

  • Encryption: TLS everywhere in transit; KMS-encrypted RDS and S3 at rest.
  • Minimal student PII: students log in with a school-issued username and school code, not a personal email; no birthdate is collected beyond grade level.
  • Rate limiting: per-route, per-IP sliding window in Redis (nestjs-throttler), tightened further on /auth/*.
  • Audit trail: grade changes, super-admin impersonation, and any bulk data export are written to an append-only AuditLog, queryable by school administrators for their own school.
  • Least-privilege IAM: each ECS task role can reach only the S3 prefixes and RDS/Redis endpoints it needs — the worker service, not the API, is the only role permitted to call OpenAI.
  • Backups & DR: RDS automated backups (7-day retention) plus a weekly snapshot copied to a separate account and region.
16

Observability & scalability

  • Logging: structured JSON (pino) shipped to CloudWatch, correlated by request ID across the API and the worker that eventually processes its enqueued job.
  • Metrics & tracing: OpenTelemetry across API and workers, visualized in CloudWatch/Grafana; BullMQ queue depth is a first-class metric, not an afterthought.
  • Scaling: ECS services autoscale on CPU for api-service/ws-service, and on queue depth for worker-service — a backlog of ungraded quizzes scales workers directly, rather than waiting on a CPU threshold that async jobs barely move.
  • Database: RDS Proxy for connection pooling; a read replica planned for Phase 3 to keep reporting queries off the OLTP path as school count grows.
  • Rollout control: feature flags gate new capabilities per school, so a pilot district can run ahead of the rest without a separate deployment.

Rollout roadmap

Three phases, widening by grade coverage, language, and geography in that order.

PHASE 1

Pilot — Dili & Baucau

Core auth and all six roles; Math and Tetum-literacy curriculum for grades 1–3; auto-graded quizzes; parent progress view. Tetum and English locales live; Bahasa Indonesia content drafted but not yet published.

PHASE 2

Full grade range, AI tutor

Grades 1–6 across all subjects; adaptive difficulty engine and AI tutor chat go live; Bahasa Indonesia locale published; teacher analytics dashboards; WebSocket live-classroom sessions.

PHASE 3

National rollout

Expansion beyond the pilot municipalities; principal and super-admin analytics suite; resilient client-side caching for schools with intermittent connectivity; SMS notification fallback for parents without a smartphone.
